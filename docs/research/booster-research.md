# Frameforge booster research

Date: 2026-10-13. Scope: what game boosters and gamer communities do to speed up Windows for games, and which tweaks have real evidence.

## Method and honesty notes

- Fetched or searched this session (full list under Sources): Hone's Game Mode research page, Microsoft's Quality of Service doc, the PresentMon repo, the LagoFast homepage, and web searches on AMD X3D/Game Bar, VBS cost, and windowed-game optimizations.
- Everything else (registry value names, powercfg GUIDs, API names, service names) comes from the author's prior knowledge of Windows internals. Those items are marked `[verify]` where a typo would be costly. Before shipping, check each one on a real Win10 and Win11 machine. The `[verify]` marker is a to-do for the implementer, not a claim that the thing is doubtful.
- Reddit, Blur Busters and guru3d were not fetched. Statements about community consensus are summaries of well-known threads, labelled "anecdotal". No text was copied from any source.
- Hone's published numbers (+24 to +28% average FPS in VALORANT on a 9800X3D) came from a tuned, debloated machine with every option enabled at once. That test shows no per-setting attribution and has no repeat-run variance. Treat it as vendor marketing, not as proof of effect size. Our own PresentMon A/B feature (section 3.5) exists to avoid this problem.

## 2. Prioritized recommendations

### 2.1 Implement now (safe, reversible, evidenced)

1. **Power-throttling opt-out for the game process** (item 3). User-level, per-process, self-cleaning, documented by Microsoft.
2. **PresentMon before/after benchmark** (item 33 and section 3.5). The core of an evidence-based product. Do this first so every other feature can be measured.
3. **GPU preference per exe on multi-GPU systems** (item 8). Largest real-world win on hybrid laptops and trivially reversible.
4. **Game Mode on, with capture and background recording off** (items 4, 5). Keep Game Bar core and its game-detection registration; only turn off capture and the startup panel.
5. **Ping/jitter/loss diagnostics** (item 24) in place of a fake route booster.
6. **Startup apps manager via StartupApproved toggle** (item 29). Reversible exactly, no deletion.
7. **Service allowlist pause with strict deny list and crash recovery** (section 3.1). Safe only with the safeguards below.
8. **Smart P-core targeting via CPU sets**, enabled only on hybrid Intel with at least 6 P-core logical groups left, and skipped when Win11 Thread Director is active unless the user opts in (section 3.3).
9. **Read-only system report**: VBS/HVCI state, HAGS state, Game Mode, Windows build, GPU driver date, power plan, core parking value, pending reboot.

### 2.2 Implement as opt-in advanced with warnings

- Fullscreen optimizations off per exe (item 6).
- Windowed-game optimizations (flip model upgrade) on (item 7). Warn about tearing.
- HAGS toggle (item 9). Show benchmark button; reboot required.
- MPO off (item 10), shown only under a "stutter/flicker troubleshooting" heading.
- Core parking disable (item 12), disabled by default and hidden on dual-CCD X3D and on battery.
- Standby list purge as a manual button (item 27).
- NIC interrupt moderation and Wi-Fi power saving (items 22, 23), behind a per-adapter confirmation.
- Shader cache cleanup (item 31) as a troubleshooting action.
- Global timer resolution flag (item 14), already gated.
- Ultimate Performance plan (item 11), already consent-gated.

### 2.3 Inform only

- VBS / Memory Integrity (item 17). Show the measured range (roughly 0 to 8%, largest at 1080p CPU-bound), link to Windows Security, and let the user decide. Never change it silently or at all.
- Mouse polling rate (item 16): point to the device vendor's software.
- Visual effects (item 28), temp cleanup (item 30): describe honestly as non-FPS.
- Driver age (item 32): show, do not install.
- Ethernet over Wi-Fi advice.

### 2.4 Do not implement

- Nagle / TcpAckFrequency / TCPNoDelay (item 19): games use UDP, no evidence.
- NetworkThrottlingIndex / SystemResponsiveness / MMCSS Games tweaks (item 20): defaults already favour games; changes can hurt.
- QoS/DSCP policy (item 21): stripped before it leaves the home router.
- Relay "game VPN" routing (item 34): needs a server fleet we do not have; claiming otherwise would be misleading.
- Disabling Defender, Windows Update permanently, SysMain permanently, UAC, VBS, Spectre mitigations, or the Firewall.
- Global `PowerThrottlingOff`, `DisableUserPresenceQos` as defaults.
- "RAM cleaner" that trims all working sets (`EmptyWorkingSet` on every process): makes things slower after the next page-in.
- REALTIME priority, forced affinity to one core, or any process termination of security software.
- Any registry "tweak pack" with no measurement.

## 3. Implementation notes for the four planned items, plus benchmarking

### 3.1 Service allowlist pause

**Principle:** stop, never disable. Do not change the service start type. That way a crash or power loss leaves the machine in a state that heals itself on reboot for auto-start services. Persist a journal (`%APPDATA%\Frameforge\session-services.json`) before the first stop. On every app and helper start, check the journal and restore.

**Procedure per service:**

1. Open with `ServiceController` / `OpenService(SERVICE_QUERY_STATUS | SERVICE_STOP | SERVICE_START)`. Requires the elevated helper.
2. Record `Status`, `StartType` (including delayed-auto flag and trigger-start info) and `CanStop`.
3. Only act if `Status == Running` and `CanStop`. Skip otherwise.
4. Enumerate `DependentServices` (`EnumDependentServices`). If any dependent is on the deny list, skip. Otherwise Windows will stop the dependents too, and the journal must also contain them.
5. `Stop`, with a 5 second timeout. A hang means log it and move on. Do not kill the service host.
6. In a `finally`, on session end, on app exit and on next launch, start the services in reverse dependency order, but only if the journal says we stopped them.

### 3.3 P-core detection and CPU-set pinning (Intel hybrid)

1. Call `GetLogicalProcessorInformationEx(RelationProcessorCore, ...)` (two calls, size then data). Each `SYSTEM_LOGICAL_PROCESSOR_INFORMATION_EX` of `Relationship == RelationProcessorCore` carries `PROCESSOR_RELATIONSHIP` with `EfficiencyClass` (BYTE), `Flags` (`LTP_PC_SMT = 0x1` means the core has SMT siblings) and a `GroupMask[]`.
2. If every core has the same `EfficiencyClass`, the CPU is not hybrid. Do nothing.
3. Otherwise the highest `EfficiencyClass` is the performance class (P-cores). Lower values are efficiency (E) cores. Intel client chips typically report P = 1 and E = 0. Do not hard-code that: use max/min.
4. Do not use the EfficiencyClass to infer SMT; a P-core with `LTP_PC_SMT` has two logical processors in its `GroupMask`.
5. Apply with **CPU sets**, not hard affinity: enumerate `GetSystemCpuSetInformation` (it gives `CpuSet.Id`, `EfficiencyClass`, `CoreIndex`, `LastLevelCacheIndex`, `Group`, `LogicalProcessorIndex`), choose the IDs where `EfficiencyClass == max`, and call `SetProcessDefaultCpuSets(hProcess, ids, count)`. Restore with `SetProcessDefaultCpuSets(hProcess, NULL, 0)`. CPU sets are a soft hint to the scheduler, they coexist with EcoQoS and anti-cheat better than `SetProcessAffinityMask`, and they do not break when the process is not in group 0.
6. Fallback for Win10 or when `SetProcessDefaultCpuSets` fails: `SetProcessAffinityMask` using only groups < 64 logical processors, remembering the old mask from `GetProcessAffinityMask`.
7. Conditions to apply: at least 6 P logical processors available (4 P cores with SMT = 8 threads is the realistic minimum, fewer risks hurting CPU-hungry titles). Skip on Win11 when Thread Director is healthy unless the user opts in: Thread Director with the game in the foreground already picks P-cores. The Win10 path benefits more.
8. Also use CPU sets for **AMD dual-CCD X3D** detection of the V-Cache CCD: group CPU sets by `LastLevelCacheIndex`, then use `GetLogicalProcessorInformationEx(RelationCache)` to read each L3 size. The CCD with the largest L3 is the V-Cache one. Do not park, just offer "keep game on V-Cache CCD" as an advanced toggle, but only when the AMD driver is not already doing it (check by reading the process's CPU set after launch).
9. The helper must apply it after the game window exists and a short delay, since launchers spawn children. Apply to the game process and its child processes only if they share the install folder.

### 3.4 Core parking via powercfg

- Sub-group `SUB_PROCESSOR` = `54533251-82be-4824-96c1-47b60b740d00`.
- `CPMINCORES` (Processor performance core parking min cores) = `0cc5b647-c1df-4637-891a-dec35c318583`. Value is a percentage of cores that must stay unparked, 0 to 100. `CPMINCORES1` for the second core class on hybrid systems is `0cc5b647-c1df-4637-891a-dec35c318584` `[verify]`.
- The setting is hidden from the power UI by default. Reading and writing through `powercfg` works regardless of the hidden attribute.

**Read current values** (parse output; do not assume English, search for the GUID then the two `0x` hex values for AC and DC):
`powercfg /query SCHEME_CURRENT SUB_PROCESSOR CPMINCORES`
Better, get the active scheme GUID first with `powercfg /getactivescheme` and pass that GUID, so you write to the same scheme you read.

**Apply** (active scheme only):

```
powercfg /setacvalueindex <activeGuid> SUB_PROCESSOR CPMINCORES 100
powercfg /setdcvalueindex <activeGuid> SUB_PROCESSOR CPMINCORES 100   (only if not on battery policy exclusion below)
powercfg /setactive <activeGuid>
```

**Restore** with the saved AC and DC values and `/setactive` again. Journal the previous values and scheme GUID to disk before changing, as with services. If the user changes scheme during the session, restore to the scheme we modified, not the new active one.

Guidance:

- If the saved value is already 100, do nothing and tell the user parking is already off. This is the most common case on modern desktops.
- Skip DC (battery) entirely by default. Parking exists to save power on battery.
- Native alternative without the CLI: `PowerWriteACValueIndex` / `PowerWriteDCValueIndex` / `PowerSetActiveScheme` from powrprof.dll, same GUIDs.
- **AMD dual-CCD X3D (7950X3D, 7900X3D, 9950X3D, 9900X3D):** the 3D V-Cache driver relies on parking the non-cache CCD when a game is detected (Notebookcheck, hwbusters, FPS Review). Forcing CPMINCORES to 100 can defeat the mechanism and lower FPS. Detect CPU model via WMI `Win32_Processor.Name` or the L3 layout above, and block the feature with an explanation. Single-CCD X3D parts (5800X3D, 7800X3D, 9800X3D) are unaffected but also gain nothing.
- Intel hybrid: on Win11 parking is largely managed by the hardware scheduler. Evidence for a gain is thin. Keep opt-in.
- Measurement: use the PresentMon A/B harness. Do not claim FPS gains without it.

### 3.5 Before/after benchmark with PresentMon

- PresentMon is MIT-licensed (Intel, copyright 2017 to 2024) per its GitHub repo. Ship the licence text alongside the binary. Bundle the console application (`PresentMon-<ver>-x64.exe`) and spawn it from the helper.
- Needs ETW access. Per the repo, the user must be an administrator or a member of "Performance Log Users"; without full admin, some process names can show up as `<unknown>`. Run it from the existing elevated helper.
- Typical invocation (v2 console; verify flags against the version you bundle): `PresentMon.exe --process_name game.exe --output_file run1.csv --timed 60 --terminate_after_timed --stop_existing_session --no_console_stats`. `[verify]` on `--delay`, `--stop_existing_session` and column names; v1 used `msBetweenPresents`, v2 uses `FrameTime`.
- From the CSV compute: average FPS = 1000 / mean(frame time ms); 1% low and 0.1% low = FPS at the 99th and 99.9th percentile of frame time (pick one definition and say which); also show frame-time standard deviation and stutter count (frames above 2x median).
- Method for credible A/B: same save-game or scripted scene, 30 s warm-up, at least 3 runs per condition, interleave (A B A B), report mean and run-to-run spread. If the difference is smaller than the spread, say "no measurable change". Also record CPU temp and background load; thermal throttling after repeated runs ruins A/B.
- Hone's own results (+24 to +28% average) mixed all options at once. The product should instead let users benchmark each toggle, which turns the research table's "anecdotal" entries into a per-machine "measured" verdict.

## 4. Game icon extraction

Priority order per game, each falling back to the next:

1. **Launcher artwork (best quality)**
   - **Steam:** `<Steam>\appcache\librarycache\<appid>\` holds `library_600x900.jpg` (portrait), `library_hero.jpg`, `header.jpg`, `logo.png`, and `<hash>.jpg` icon files. Since the 2023 client update many files sit one level deeper in a hash-named subfolder, so search the folder recursively and pick by file name. Find the Steam folder from `HKCU\Software\Valve\Steam` `SteamPath`, and library folders from `steamapps\libraryfolders.vdf`; names come from each `appmanifest_<id>.acf`. Fallback is Valve's public CDN `https://cdn.cloudflare.steamstatic.com/steam/apps/<appid>/header.jpg` (and `library_600x900.jpg`), downloaded once and cached. `[verify]` host, Steam has moved CDN hostnames before.
   - **Epic:** `C:\ProgramData\Epic\EpicGamesLauncher\Data\Manifests\*.item` JSON files give `DisplayName`, `InstallLocation`, `LaunchExecutable`, `CatalogNamespace`, `CatalogItemId`. There is no local artwork cache you can rely on, so use the exe icon (step 2). Do not scrape Epic's unofficial catalog endpoints.
   - **GOG:** registry `HKLM\SOFTWARE\WOW6432Node\GOG.com\Games\<productId>` has `gameName`, `path`, `exe`. Optional artwork from the public `https://api.gog.com/products/<id>?expand=images` endpoint `[verify]`; Galaxy's `galaxy-2.0.db` is an internal SQLite file and may change, so use it only as a read-only convenience.
   - **Xbox / Microsoft Store:** read the package `AppxManifest.xml` (`Square150x150Logo`, `Square44x44Logo`) and resolve the scale-qualified file (for example `*.scale-200.png`) in the install folder.
   - **Others (Ubisoft, EA, Battle.net, Rockstar):** use the exe icon.
2. **Exe icon:**
   - In Electron: `app.getFileIcon(exePath, { size: 'large' })` returns a `NativeImage`. On Windows, `large` is 32x32 (the platform-dependent sizes are small 16, normal 32, large 32 on Windows, per docs `[verify]`), so it looks blurry at card size.
   - For crisp icons use the .NET helper: `IShellItemImageFactory.GetImage` (size up to 256x256, supports `SIIGBF_ICONONLY`), or `SHGetFileInfo` with `SHGFI_LARGEICON` plus `SHIL_JUMBO` via `SHGetImageList`. Save as PNG.
   - Many launchers' exe is a stub (`launcher.exe`). Resolve the real game executable from launcher metadata first, then pick the biggest exe in the install folder if unknown.
3. **Generated placeholder:** first letter on a color derived from a hash of the name. Cheap and always works.
4. **Optional, user-enabled online artwork:** SteamGridDB, which needs the user's own API key and a one-time consent, since it sends the game name to a third party. Off by default.

**Caching:** store in `userData/icons/<sha1(source-path + mtime)>.png`, resize to a few fixed sizes (64, 256), and invalidate when the source file changes. Do not ship or redistribute downloaded artwork. Display it locally only, because it belongs to the game publishers.
