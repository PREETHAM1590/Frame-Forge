# Game-booster feature catalog -> Frameforge mapping

Source list: a local, untracked list of 87 commonly offered game-booster features. Evidence grades: **A** documented by Microsoft (or NVIDIA for the DLSS key), **B** value present on the reference PC (Windows 11 Pro 26100, RTX 4050 laptop) and it is the setting the Windows UI itself writes, **C** community only.
Anything graded C or not confirmable is `[unverified]` and is **not applyable**.

Classes: `have` = already exists, `impl` = implement now (HKCU, no admin), `adv` = implement as Advanced opt-in (admin: HKLM / bcdedit / powercfg), `sec` = implement in the separate "Security trade-offs" category (user override of H4, extra guardrails below), `info` = information only, `no` = not offered, `dup` = duplicate of another row.

Finding from the real round trip on the reference PC: `HKCU\Software\Policies` is write-protected for a non-elevated user (the helper got "access denied"), so the four items that rely on a policy key (items 8, 23, 41, 46) use the machine policy hive and are Advanced administrator items instead of current-user items.

Common rules for every `impl`/`adv`/`sec` item: typed definition, exact settings, prerequisites, risk label, pre-change capture of the exact prior state (absent included), preview, confirmation, post-apply re-read, rollback to the exact prior state, Activity row, tests. Admin items use the helper's self-elevation (one UAC prompt per helper call, reads of HKLM need none). Nothing is run elevated during testing; admin code is exercised through fakes.

## Security trade-offs (user override of H4)

Items 21, 26, 29, 31, 36, 37, 40, 43, 44, 78, 79 are applyable only in the separate **Security trade-offs** category. Guardrails: off by default, in no preset, excluded from any multi-select apply; red High risk label with a plain-language consequence; confirmation needs the user to type the item name; restore-point offer in the preview; exact prior capture and rollback (absent included) re-read after both; "Pending restart" while a reboot-required item is applied; Dashboard banner with one-click "Restore all security settings"; the server refuses a confirm without the acknowledgement. Items 39 and 42 stay info-only [unverified]. Tamper Protection is only read, never bypassed. Never applied for real during development.
